### Блокер S7 №1 (новый) — explain_rejections теряет причину

Кандидат can_run=True, can_cover_window=False теперь попадает в explain_rejections
(матчит правку rejection.py), но с out_of_stock=False и blockers=() — причины
отказа в терминах core/fit.py у него нет физически, он просто не набрал часов.
Подтверждено кодом: core/fit.py:95-97, can_run = not blockers.

Усугубляется тем, что explain_rejections вызывается ТОЛЬКО при пустой выдаче
(ADR-031, api/app.py:224-229). Единственный сценарий, где эти записи вообще
видны человеку, — когда ВСЕ кандидаты непокрывающие. api/rejection_summary.py
строит reasons только из blockers (пустой цикл при пустом кортеже) — человек
получит «не підійшло: N» без единой строки причины.

Требует новый FitBlocker в core/ — второй слой, отдельная сессия. Между этой
сессией и сессией с FitBlocker деплоить нельзя — блокер S7, не «желательно».

### Принятые решения, ждущие реализации
- **Лесенка вместо одного списка:** три ЦЕЛЫХ решения по запасу автономности
  («мінімум, що витягне» / «із запасом» / «на кілька діб»), не свободная
  комбинация «інвертор 1-2-3 × АКБ 1-2-3». Внутри карточки — альтернативные
  продавцы ТОГО ЖЕ SKU, свёрнутым списком. Требует ADR и правки matching/+api/.
- **Оффер выбирается ПОСЛЕ ранжирования, а не до.** Кандидат для matching/ —
  спека, не пара «спека + магазин». Цена для сортировки — минимальная среди
  in_stock. Требует ADR.
- **Продавец из сети с договором идёт первым оффером**, магазин без
  партнёрской программы помечается.
