### Закрыто
- `GET /` работает: форма выбора приборов + результат на одной странице.
  Коммит 714d650, подтверждён на origin/main через git fetch.
- **Формат URL зафиксирован навсегда:**
  `/?p=fridge_medium,led_bulb_9w:3&h=4&t=4.32&f=58`
  Двоеточие как разделитель количества (не звёздочка — символ разметки
  в мессенджерах). Коды сортируются алфавитно. Количество=1 не пишется.
  Дефолтный тариф в ссылку не попадает (флаг `tariff_is_default`).
- **302-нормализация.** HTML-форма умеет только repeated-параметры
  (`?p=a&p=b`), канонический вид — с запятыми. Неканоническая строка
  запроса редиректится; сам канонический URL хопа не даёт.
- `api/query_params.py` — парсер, не поднимает исключений ни на каком
  входе (битая пересланная ссылка = потерянный человек). 10 тестов.
- `api/rejection_summary.py` — перевод `RejectionReason` в агрегат.
  `explain_rejections` впервые вызывается из живого кода.
- `api/templates/base.html`, `index.html`. Аккордеон на каждую категорию,
  топ-6 всегда раскрыты. Счётчик выбранного в `<summary>` виден
  в свёрнутом виде, живо обновляется ванильным JS (progressive
  enhancement, без JS цифры с сервера верны).
- `_calculate(request)` вынесена в `api/app.py` — общий путь расчёта для
  `POST /api/v1/recommendations` и `GET /`. Два роута, считающие
  по-разному, были вопросом времени.

  ADR-009 не нарушен: ядро по-прежнему получает явный параметр.

### Замечания владельца по выдаче (слой matching/, отдельная сессия с ADR)
- Генераторы не появляются в выдаче — не из-за `f`, значит проигрывают
  по сортировочному ключу (ADR-018/029).
- Холодильник + котёл, 4 ч → пустая выдача. 48 кандидатов, 18 недоступны.
- Киты вытесняют станции и повербанки.
- `laptop_charger_65w_ac` (AC) vs `laptop_usb_c_pd_65w` (DC): человек
  выбирает «ноутбук» и не знает, что к первому повербанк не подойдёт.
  Домен работает верно, формулировка в справочнике вводит в заблуждение.
  Задача S8.
